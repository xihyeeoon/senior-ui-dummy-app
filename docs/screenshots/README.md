# 재현 근거 스크린샷 (실제 신한 SOL뱅킹 캡처)

> **도메인 변경(연구 v6):** 대상 앱이 KB스타뱅킹 → **신한**으로 바뀌었습니다.
> 기존 KB 캡처는 삭제했고, 이 폴더는 신한 캡처 기준으로 새로 구성했습니다.

A1(일반)·A2(고령자) 화면을 원본에 맞춰 재현하기 위한 캡처를 넣는 곳입니다.
여기 이미지는 **참조용**이며 앱에 번들되지 않습니다(`pubspec.yaml`의 `assets:`에 등록 안 함).

## 신한 고령자 모드의 구조 (v6에서 확인)

**홈은 일반 모드와 다르지만(진짜 재설계), 세부 태스크 화면은 일반 모드와 공유**한다.
그래서 폴더도 그 구조를 따른다 — 홈만 일반/고령자로 나누고, 세부(공과금·이체)는 공유라 나누지 않는다.

```
docs/screenshots/
├─ 01_메인/
│  ├─ 일반홈/          # A1 진입 홈
│  └─ 고령자홈/        # A2 진입 홈 (일반과 다름)
├─ 02_메뉴/            # 전체메뉴 — 스크롤/탭 조각 순서대로
├─ 03_공과금납부/      # 공과금 플로우 (A1·A2 공유 세부)
└─ 04_이체/            # 이체 플로우 (A1·A2 공유 세부)
```

- **이체** 태스크 = A1/A2/C 3조건 → 일반홈·고령자홈 둘 다 필요.
- **공과금** 태스크 = A1/C 2조건 (배포된 고령자 모드 부재) → 일반 경로만.
- 고령자 모드에 별도 "메뉴"가 있으면 `02_메뉴/고령자/`를 추가로 만든다. (확인 필요)

## 넣는 법

**파일명은 신경 쓰지 말고 순서만 맞춰 주세요.** 폴더 안에서 이름순 정렬되므로
`01.png`, `02.png` … 번호만 붙이면 됩니다. 스크롤이 길면 조각내서 여러 장 주셔도 됩니다.
단계 경계가 애매하면 한 폴더에 순서대로 다 넣고 알려 주세요 — 캡처를 보고 제가 나눕니다.

## 부분만 있어도 됩니다

없는 단계는 **추측해서 만들지 않습니다.** 캡처가 있는 화면만 재현하고,
나머지는 코드에 `템플릿` 주석으로 미완성임을 명시합니다.
A1이 "충실 재현 baseline"이라는 주장을 지키려면 이 구분이 중요합니다.
근거·의도적 차이·미확인 항목은 [`docs/fidelity.md`](../fidelity.md)에 기록합니다.

## 개인정보 주의

실제 앱 캡처에는 **본인 계좌번호·잔액·이름·거래내역**이 찍혀 있습니다.
연구 원칙(실거래·실제 금융정보 0)은 앱 코드뿐 아니라 저장소 전체에 적용합니다.

- 이 폴더는 `.gitignore` 처리되어 있습니다(이 README만 커밋). 캡처는 커밋되지 않습니다.
- 히스토리에 한 번 들어간 이미지는 나중에 삭제해도 영구히 남으므로, 처음부터 커밋하지 않습니다.
- 재현에 쓰는 값(이름·계좌·잔액)은 앱 코드에서 전부 더미로 치환합니다(`lib/data/`).
