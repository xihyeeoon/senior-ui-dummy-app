# A1 ↔ 실제 KB스타뱅킹 충실도 대조표

A1은 **원본 충실 재현 baseline**이다. 원본과 다른 점은 모두 여기에 근거와 함께 남긴다.
근거 캡처는 `docs/screenshots/`(커밋 제외, 로컬 보관).

> **이체에는 인증 화면이 없다.** 캡처는 확인 시트 → 바로 완료다. 1원 소액이라
> 간편이체로 인증이 생략된 것으로 보인다. 큰 금액에서는 인증이 뜰 가능성이 있어
> **인증 화면은 과제 1·2 양쪽 모두 근거가 없는 상태**다.

> 캡처가 없는 화면은 추측으로 만들지 않는다. 만든 것은 코드에 `템플릿` 주석으로 명시한다.

**4~6번을 캡처하지 못한 이유**: 실제 고지서(전자납부번호)가 없어 `[조회]` 이후로 진행할 수 없었다(2026-07-16).
현재 `[조회]`는 10자리를 채우면 활성화되지만, 누르면 "아직 재현 전" 안내만 띄운다.

### 구조상 발견

- **"공과금 종류 선택"은 별도 화면이 아니다.** `공과금 납부/조회` 메인 화면 안의
  `세금`(9종) / `생활공과금`(6종) 2열 그리드다. 전기/TV를 누르면 바로 입력 화면으로 간다.
- 실제 경로: `메뉴 → 공과금 → 공과금 납부/조회 → 생활공과금 > 전기/TV → 전자납부번호 입력 → [조회] → …`

## 원본과 의도적으로 다른 점

### 1. 전체메뉴 · 최근/My메뉴에서 [공과금 납부/조회] 칩 제외

- **원본**: `최근/My메뉴`에 `[환경설정 ☆]` `[공과금 납부/조회 ☆]` 두 칩 (`기본_메뉴(1).png`)
- **A1**: `[환경설정 ☆]` 만
- **사유**: 해당 칩은 캡처한 기기가 공과금을 최근 사용해 생긴 **개인화 상태**이지,
  앱의 기본 상태가 아니다. 그대로 재현하면 메뉴 진입 즉시 **1탭으로 과제가 종료**되어
  A1의 탐색 비용(섹션 12개 중 공과금은 4번째)이 사라진다. A1은 바닥 baseline이므로
  탐색 비용이 곧 측정 대상이다.
- **회귀 방지**: `test/widget_test.dart` — "메뉴 최상단에 공과금 바로가기가 없다 (탐색 비용 유지)"
- **후속**: 실험폰에 앱을 새로 설치한 초기 상태에서 `최근/My메뉴`가 어떻게 보이는지
  캡처를 받으면 그에 맞춰 정정할 것. (비어 있는지 / 섹션 자체가 없는지 / 기본값이 있는지)

### 2. 개인·금융정보 더미 치환

- 이름·계좌번호·잔액·거래내역은 전부 더미(`홍길동님`, `000000-00-000000`, `12,500원`).
- 공과금 메인의 `○○○님, 납부할 세금을 확인해보세요`도 캡처의 실명 → `홍길동님`으로 치환.
  회귀 방지: `test/widget_test.dart` — "공과금 섹션의 공과금 납부/조회로 공과금 메인에 진입한다"
- 연구 원칙: 실거래·실제 금융정보 0 (`README.md`).

### 3. 공과금 입력 키패드 — 이체 캡처를 근거로 채택

- **원본**: 공과금 전자납부번호 입력란을 탭한 화면을 캡처하지 못했다(키패드가 닫힌 상태만 있음).
- **A1**: 배열이 고정된 일반 키패드(`KbNumberKeypad`) 사용.
- **근거**: 같은 성격의 숫자 입력인 **이체 금액 화면**(`transfer/기본_이체(2).png`)이
  섞이지 않는 고정 배열(`1~9 / 00 · 0 · ←`)을 쓴다. 전자납부번호는 비밀번호가 아니므로
  보안 키패드(숫자 섞임)를 쓸 이유가 없다.
- **한계**: 해당 화면 자체의 캡처가 아니므로 **추정**이다. 고령자에게 "매번 섞이는 키패드"와
  "고정 배열"은 입력 난이도 차이가 커서, 확인되면 즉시 정정해야 한다.
- 숫자가 섞이는 `KbSecurityKeypad`는 코드에 남겨두었으나 **현재 어느 화면도 쓰지 않는다**
  (인증 화면 캡처를 받으면 그때 쓰일 수 있음).

### 4. 이체 완료 화면의 일러스트 대체

- **원본**: 곰 캐릭터 + ₩ 코인 일러스트 (`transfer/기본_이체(5).png`)
- **A1**: 동일 위치·크기의 원형 아이콘으로 대체 (저작권 자산이라 재사용하지 않음).
- 레이아웃·문구·버튼 구성은 캡처 그대로.

### 5. 개발용 요소

- `KbDevBar`(상단 검정 바)는 개발/조건 이동용. **실제 실험 빌드에서는 제거**.
- 과제 경로 밖 요소는 `OutOfScope`로 감싸 "실험 범위 밖" 안내만 띄운다.
  자유 탐색 중 앱이 깨지지 않게 하기 위함이며, 실험 빌드에서는 조용한 no-op으로 바꿀 수 있다.

## 캡처 대기 중 (추정으로 둔 부분)

| 항목 | 현재 처리 | 필요한 캡처 |
|---|---|---|
| **인증 화면** (과제 1·2 공통) | 없음 | 인증이 뜨는 금액으로 이체. **최우선** |
| 공과금 `[조회]` 이후 (확인→완료) | 안내만 띄움 | 실제 고지서 필요 |
| 공과금 입력란 **키패드** | 이체 근거로 일반 키패드 채택 | 입력란 탭 → 키패드 뜬 화면. **서류 없이 촬영 가능** |
| `[조회]` **활성** 상태 색 | KB 주색인 노랑으로 추정 | 10자리 입력된 상태 화면 |
| 실험폰 초기 `최근/My메뉴` | `[환경설정]`만 노출 | 앱 새로 설치 후 메뉴 최상단 |
| A2(간편홈)의 과제 1·2 경로 | 없음 | 간편홈에서 같은 과제 수행 |

> 키패드·인증은 고령자에게 가장 큰 장벽이라, 추정으로 두면 A1의 난이도가 실제와 달라진다.

## 미검증 항목

- 캡처는 **iOS**(1179×2556)이나 실험폰은 **안드로이드**다. 두 OS 간 KB 앱 UI 차이는 미확인.
  기본 홈·전체메뉴 모두 동일 캡처 기준으로 만들었으므로 일관성은 있으나,
  실험폰 실물과 대조가 필요하다.
- 전체메뉴 칩 바의 `[∨]` 더보기(카테고리 펼침) 동작은 캡처에 없어 미재현 (범위 밖 처리).
