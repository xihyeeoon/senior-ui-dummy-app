# A1 ↔ 실제 신한 SOL뱅킹 충실도 대조표

A1은 **원본 충실 재현 baseline**이다. 원본과 다른 점은 모두 여기에 근거와 함께 남긴다.
근거 캡처는 `docs/screenshots/`(커밋 제외, 로컬 보관).
충실도 기준(v6 §4.5): 핵심 태스크 절차·핵심 정보/기능·요소 크기·전반 레이아웃은 일치, **아이콘 세부·미세 색·장식은 근사 허용**.

## 원본과 의도적으로 다른 점

### 1. 개인·금융정보 더미 치환 (연구 원칙: 실금융정보 0)

- 이름·계좌·잔액·거래내역·주소는 전부 더미(`lib/data/sh_dummy.dart` 한 곳).
- 이체: 받는분 예금주 `김철수`, 출금계좌 `신한 110-000-000000`, 출금가능 `1,000,000원`.
- 공과금 납부정보/완료: 고객명 `홍길동`, 전자납부번호 `1700000000`, 지정계좌 `315…0000`, 주소 `○○동 ●●●-●`, 납부금액 `2,160원`(더미), 납부일 고정.
- 캡처의 실명·실계좌(예: 선의상·110-521-079009·31590101637915)는 코드 어디에도 남기지 않음.

### 2. 이체 정답/오류 판정 — 원본에 없는 **실험 장치**

- 실제 앱은 유효 계좌면 진행한다. 본 더미는 **과제 성공 측정**을 위해 정답을 고정한다.
- **정답 = 신한 + `110234567890`**. 규칙은 `ShDummy.checkTransfer`/`isAccountValid`.
  - 계좌 오답 → 진입 [다음]에서 **ELB00016** 팝업(즉시 차단)
  - 은행 오답(계좌는 맞음) → 확인 [보내기]에서 **ETA00325** 팝업
  - **백도어**: 계좌 `0` 한 글자 → 은행 무관 통과(실험자 편의, 은행 선택은 필수)
- 오류 팝업의 코드·문구는 실제 캡처(ETA00325/ELB00016) 그대로.

### 3. 로고·아이콘 — 실제 캡처 누끼 + 색원 폴백

- 은행 38 / 증권사 29 / 공과금 항목 18 / 홈 헤더 4 아이콘 = **실제 앱 캡처를 누끼 처리**해 `assets/`에 번들(비상업 학술 재현, 지시적 사용).
- 파일명은 웹 URL 인코딩 문제를 피하려 ASCII 인덱스(`b0~b37`, `s0~s28`, `c1~c18`, `h1~h4`).
- 관세는 캡처가 없어 국고금과 동일 태극 아이콘(`b37`=`b36`) 공유. 미제공 항목은 색원(이니셜) 폴백(`ShBankMark`).
- 캐릭터(곰·하리보 등) 일러스트는 저작권 자산이라 아이콘/도형으로 근사.

### 4. 카메라 촬영은 모크

- `a1_bill_pay_camera.dart`는 촬영 화면만 재현하고 셔터를 누르면 납부정보로 진행한다. 실제 OCR 인식은 없다.

### 5. 개발용 요소

- `ShDevBar`(상단 검정 바)는 개발/조건 이동용. **실제 실험 빌드에서는 제거**.
- 과제 경로 밖 요소는 `OutOfScope`로 감싸 "실험 범위 밖" 안내만 띄운다(자유 탐색 중 앱이 깨지지 않게). 실험 빌드에서는 조용한 no-op으로 바꿀 수 있다.
